# translate PDF 图表自动裁剪与嵌入设计

## 背景

当前 `read-pdf` 能识别含位图或矢量视觉内容的页面，并为这些页面渲染整页 PNG；但是提取包中的
`image` block 只有顺序和空内容，没有可复用的页面坐标。当前 `translate` 只在译文中写入“见原书
图 X.X”的提示，不能把图表直接放到对应译文附近。

本设计为 `translate` 增加全自动的关键视觉内容处理能力：尽量裁剪、验证、持久化并嵌入关键图表；
无法可靠裁剪或定位时自动降级为原书定位提示，不引入人工确认步骤。

## 目标

1. 从 PDF 提取包获得稳定、可校验的页面尺寸和 block 坐标。
2. 用确定性脚本按 PDF 坐标裁剪视觉区域，避免依赖模型徒手估算像素位置。
3. 在译文中按原书阅读顺序嵌入关键图表、流程图、几何图和结构示意图。
4. 优先把可忠实转换的表格写为 Markdown，把公式写为 LaTeX。
5. 对裁剪边界或译文插入位置不可靠的视觉内容自动写入原书提示，不阻塞整章翻译完成。
6. 中文和英文技能契约、模板与测试同步更新。

## 非目标

- 不保证任何 PDF 都能得到像素级完美裁剪。
- 不对页眉、页脚、Logo、边框和纯装饰元素生成资产。
- 不把所有表格和公式强制保存为图片。
- 不增加人工框选、人工确认或交互式修图流程。
- 不改变翻译笔记 `draft → complete` 的文字与内容完整性主状态机。

## 方案比较

### 方案一：提取坐标驱动裁剪（采用）

`read-pdf` 直接公开 PyMuPDF 页面坐标；裁剪脚本读取原 PDF，按坐标和 padding 渲染局部 PNG；
模型只负责视觉分类、裁剪质量复核和译文锚点选择。

优点是裁剪可重复、可测试、资源消耗低，位图和矢量图都能使用同一接口。缺点是复杂排版中的标题、
图例或跨 block 图注可能位于初始边界之外，因此仍需自动扩大边界重试。

### 方案二：模型直接从整页截图估算裁剪框（不采用）

无需调整提取包，但坐标易受 DPI、缩放和页面旋转影响，难以写出稳定的回归测试，也容易截断坐标轴、
图例和图注。

### 方案三：整页图片嵌入译文（不采用）

几乎不会漏图，但会重复原书页面、显著增加 Vault 体积，并削弱中文阅读笔记的聚焦能力。

## 总体架构

功能分为两个可独立验证的层次：

1. **PDF 几何与裁剪底座**：由 `read-pdf` 维护页面几何、block 坐标、矢量区域聚合和局部裁剪脚本。
2. **翻译视觉编排**：由 `translate` 维护视觉分类、自动重试、资产命名、译文锚点、Obsidian 嵌入和降级记录。

`translate` 不自行推导 PDF 坐标，也不复制裁剪实现；它消费 `read-pdf` 的版本化提取包和裁剪脚本。

## PDF 提取包 v2

`PDF_Extraction_Schema.json` 升级为提取包 v2，`schema_version` 和 `extractor.version` 同步升级。

每页增加必填 `page_size`：

```json
{
  "width": 595.0,
  "height": 842.0
}
```

每个 block 增加必填 `bbox`，单位为 PDF point，坐标原点和方向遵循 PyMuPDF 页面坐标：

```json
{
  "kind": "image",
  "order": 2,
  "content": "",
  "bbox": {"x0": 72.0, "y0": 150.0, "x1": 540.0, "y1": 250.0}
}
```

约束如下：

- 四个坐标必须是有限数值。
- 必须满足 `0 <= x0 < x1 <= page_size.width`。
- 必须满足 `0 <= y0 < y1 <= page_size.height`。
- block 必须继续按页面阅读顺序使用连续的 `1..N` 顺序号。
- 位图 block 使用 PyMuPDF 原始图像 bbox。
- 文字 block 使用对应文字区域 bbox，供译文锚点映射。
- 矢量视觉 block 使用参与视觉判定的区域并集 bbox，不再只返回左上角锚点。

提取器在写包前把 bbox 与页面边界求交；求交后为空的 block 不进入输出。校验器同时校验结构约束与
上述跨字段几何约束，拒绝越界、退化、非有限或版本不一致的数据。

## 局部裁剪脚本

新增 `assets/skills/read-pdf/scripts/crop_pdf_region.py`，接口为：

```bash
python3 crop_pdf_region.py <PDF路径> <物理页码> \
  --bbox <x0> <y0> <x1> <y1> \
  --padding <PDF point> \
  --dpi <整数> \
  --output <PNG路径>
```

脚本职责：

- 验证 PDF、页码、bbox、padding、DPI 和 `.png` 输出路径。
- 对 padding 后的 bbox 与实际页面边界求交。
- 通过 PyMuPDF `get_pixmap(clip=..., dpi=...)` 只渲染局部区域。
- 先写同目录临时文件，再原子替换目标文件，避免留下半写资产。
- 成功时向标准输出写机器可读 JSON，包含最终 bbox、像素宽高和文件 SHA-256。
- 失败时向标准错误写机器可读错误码，并使用非零退出码。

脚本不判断图片是否重要，也不决定译文位置，这些判断属于 `translate`。

## translate 视觉处理流程

`translate` 在视觉合并前先从初始提取包复制候选的 `pdf_page_index`、`block.order` 和 `bbox` 到本次
运行的临时视觉清单，然后继续执行既有的整页 `inspect_image` 语义补全。两类结果分别负责：

- **视觉语义补全**：读取图表含义、公式、表格或 OCR 内容，合并回提取包并接受内容完整性校验。
- **图片呈现编排**：使用临时视觉清单裁剪资产并选择译文位置；失败时只改变呈现方式，不修改已经
  通过校验的语义内容。

完成视觉语义补全后，待处理的 `image` block 必须被忠实的文字、Markdown 表格或 LaTeX 内容取代，
再由 `validate_pdf_extraction.py --require-complete` 决定内容是否完整。裁剪失败不能删除仍未读取的
公式、表格或 OCR 内容，也不能直接把含 `image` block 的页面标记为 `complete`。

### 一、候选分类

对初始提取包中的每个 `image` block，结合整页渲染图、相邻文字 block 和图注进行分类：

| 分类 | 处理 |
| --- | --- |
| `embed` | 图表、流程图、几何图、结构示意图等关键视觉内容，裁剪并嵌入 |
| `markdown` | 能忠实转换的表格，写为 Markdown，不重复嵌图 |
| `latex` | 能忠实转写的公式，写为 LaTeX，不重复嵌图 |
| `ignore` | 页眉、Logo、边框、装饰线等，与译文内容无关 |
| `reference` | 视觉内容有意义，但裁剪边界或插入位置不能可靠确认，写原书提示 |

分类结果只服务本次翻译，不改变原书事实，不把装饰元素计为缺失内容。

### 二、自动裁剪与复核

`embed` 候选执行最多两次确定性尝试：

1. 使用提取 bbox 和 12 point padding 裁剪。
2. 若复核发现标题、坐标轴、图例、图注或关键边缘被截断，使用 36 point padding 重试。

每次裁剪后用 `inspect_image` 检查目标主体是否正确、边缘是否完整、是否混入大量无关正文。第二次仍不
可靠时改为 `reference`，不再扩大到整页，也不请求用户处理。

### 三、稳定资产路径

通过 `lifeos.yaml` 解析 Vault 目录后，将最终接受的图片写入：

```text
{资源目录}/{翻译子目录}/<书名>/assets/<source-sha12>-p<物理页>-b<block-order>.png
```

同一来源、页面和 block 始终生成同一路径，恢复同一 `run_id` 时复用或原子更新该资产。不同来源通过
源文件摘要隔离。译文使用 Vault 相对路径的 Obsidian 嵌入，避免同名 `assets` 目录产生歧义：

```markdown
![[<Vault相对翻译目录>/<书名>/assets/<文件名>.png|720]]

> 图 X.X · 原书印刷页 XX · PDF 物理页 XX
```

没有可验证图号时不编造编号，说明改为：

```markdown
> 📖 见原书印刷页 XX（PDF 物理页 XX）的相关图表
```

### 四、译文插入锚点

使用以下固定优先级决定位置：

1. 同页正文明确引用图号时，放在首次引用该图的译文段落之后。
2. 没有明确引用时，按 `block.order` 放在该视觉 block 之前最近的文字 block 对应译文之后。
3. 没有可靠的正文锚点时，不嵌图；在当前小节末尾写原书提示。

该规则保证模型不能仅凭语义相似度把图移动到其他小节。

## 状态与降级语义

翻译笔记的 `status` 继续只由内容完整性门禁控制：

- 文字、OCR、公式或表格等必须内容仍缺失时，保持 `status: draft`。
- 图表裁剪边界不可靠、插入位置不可靠或局部裁剪脚本失败时，自动写原书提示；只要内容完整性门禁
  已通过，允许 `status: complete`。
- 不得把无法读取的公式或表格伪装成单纯的裁剪失败来绕过内容完整性门禁。
- 如果整页视觉语义补全本身失败，仍按内容缺失处理；原书提示只替代图片呈现，不替代语义提取。

模板的“完整性记录”增加视觉处理统计，不新增 frontmatter 状态字段：

```text
视觉处理：嵌入 N；转 Markdown N；转 LaTeX N；原书提示 N；忽略装饰 N
```

每个 `reference` 项记录物理页、印刷页、图号或 block 顺序以及降级原因。`reference` 是已完成的自动
降级结果，不列入缺页，也不降低 `completeness`。

## 恢复、覆盖与清理

- 继续使用现有 `stable(translate, source-pdf, chapter-range, extraction-hash)` 作为 `run_id`。
- 恢复 draft 时先读取已有译文和稳定资产名，避免重复嵌入。
- 同一 `run_id` 产生的新裁剪只更新其稳定命名资产。
- 用户未显式 `replace` 时，不覆盖其他已完成翻译笔记。
- 第一次裁剪失败或第二次裁剪被拒绝的临时文件必须清理；只保留译文实际嵌入的资产。
- 已降级为原书提示的候选不保留无引用 PNG。

## 双语技能与模板变更

中文和英文版本同步表达同一机器语义：

- `read-pdf/SKILL.zh.md` 与 `SKILL.en.md` 声明提取包 v2、几何字段和裁剪脚本。
- `translate/SKILL.zh.md` 与 `SKILL.en.md` 声明分类、两次裁剪、稳定资产、锚点优先级与自动降级。
- `Translation_Template.md` 中英文版本都要求在“中文对照”内部按阅读顺序放置 Obsidian 图片嵌入，并在
  “完整性记录”写视觉统计。
- 英文技能仍规定最终翻译笔记内容为中文；英文版本只用于英文安装态的技能说明。

## 测试设计

### PDF 几何与提取包

- 位图 fixture 输出精确且有界的 block bbox。
- 矢量图表 fixture 输出参与判定区域的并集 bbox。
- 文字 block 输出 bbox，排序仍为连续阅读顺序。
- v2 包缺少 `page_size` 或 `bbox` 时被拒绝。
- 非有限、退化和越界 bbox 被语义校验器拒绝。
- `schema_version` 与 `extractor.version` 不一致时被拒绝。

### 裁剪脚本

- 按 fixture 的位图 bbox 只生成公式区域，不包含上下正文。
- padding 被正确应用并限制在页面边界内。
- 非法页码、非法 bbox、负 padding、非法 DPI 和非 PNG 输出返回稳定错误码。
- 输出 JSON 的尺寸、最终 bbox 和 SHA-256 与实际文件一致。
- 写入失败不留下临时文件，也不破坏既有目标文件。

### translate 双语契约

- 中英文技能都声明五类视觉处理结果。
- 中英文技能都声明 12/36 point 两次尝试和第二次失败后的 `reference` 降级。
- 中英文技能都使用稳定资产命名和 Vault 相对 Obsidian 嵌入。
- 中英文技能都明确裁剪或位置失败不阻塞 `complete`，内容缺失仍保持 `draft`。
- 中英文模板都要求视觉统计和逐项降级记录。
- 端到端契约验证视觉 block 能按顺序变成嵌图或原书提示，并且不遗留无引用临时资产。
